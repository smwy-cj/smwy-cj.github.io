## 从内容开始

搭建个人网站时，可以先想清楚三个问题：希望读者了解什么、希望读者找到什么，以及自己以后怎样更新内容。

对一个以项目展示和技术笔记为主的网站而言，个人介绍、作品列表和知识目录就是最重要的入口。

## 为什么使用静态生成

文章在构建时生成 HTML，访问者打开链接即可读取正文。需要交互时，再由 Vue 接管筛选、搜索和主题切换。

这种结构适合内容在发布时已知、不同访问者看到相同正文的网站。修改内容后重新构建，即可发布新版本。

## 内容如何组织

目录负责长期结构，标签负责跨主题连接。比如“前端开发 / 站点实践”可以收藏建站笔记，而“GitHub Pages”标签可以同时出现在部署文章与个人站点项目中。

```text
docs/
├─ projects/       # 项目介绍
├─ journal/        # 知识与笔记
├─ public/         # 头像、图片和字体
└─ .vitepress/     # 页面主题和站点配置
```

## 自动部署的过程

提交到主分支后，GitHub Actions 安装依赖、检查类型、构建页面，并将产物发布到 GitHub Pages。

仓库设置中的 Pages 发布来源需要选择 **GitHub Actions**。本项目的使用说明写在仓库 README 中。

## 给后续维护留出空间

先保持内容格式一致，再逐步完善界面。对新项目写下背景、方法、结果与反思；对新笔记写清问题、结论和适用条件。

> 一个好的个人网站，不必一次写完。让它有一个清楚的开始，然后慢慢生长。
